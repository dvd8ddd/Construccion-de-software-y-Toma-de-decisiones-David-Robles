El Cross-Site Scripting es uno de los ataques más comunes dentro del OWASP top 10. Consiste en la inyección de código JavaScript malicioso dentro de una página Web, el cual es ejecutado en el navegador

de otros usuarios. Esto ocurre cuando una aplicación no válida correctamente los datos que recibe del usuario.

Existen tres tipos principales

Reflejado: el script viene en la URL y se ejecuta al cargar la página

Persistente: El script se guarda en la base de datos y afecta a todos los usuarios

DOM-based: Ocurre directamente en el navegador mediante manipulacion del DOM

El riesgo principal es que el atacante puede robar cookies de sesión, suplantar identidad o realizar acciones en nombre del usuario

Formas de prevenir

Escapar siempre la salida de datos, usar (<%= %>) en EJS en lugar de (<%- %>)

Validar entradas del usuario

Usar cookies con HttpOnly

Implementar políticas de seguridad como Content Security Policy con Helmet

Evitar insertar HTML dinámica sin control

Dependencias de CORS en el proyecto

Frontend del sistema, seria el dominio donde los usuarios entran al sistema

Backend, es en donde estarian las rutas de clientes, contratos, operaciones alertas y reportes

Ambiente local, seria el lugar para hacer las pruebas en la computadora

Servicio de verificación de documentos; el sistema debe verificar documentos del cliente

Servicio de listas/personas bloqueadas; el sistema debe validar clientes contra listas de personas bloquedas

Servicio de generación de reportes; es importante ya que el sistema debe generar reportes de forma segura
